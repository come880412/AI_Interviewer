# 評分標準：LeetCode coding 面試

## 釐清問題
- 5：動手前主動問清楚會影響解法的條件：輸入大小和數值範圍、空輸入或極端輸入、重複值、沒有答案時要回傳什麼、輸出格式；或明確說出自己的假設並跟面試官確認。
- 3：問了一部分，但漏了會影響解法的重要條件（例如輸入大小決定能不能用 O(n²)），或寫到一半才發現要問。
- 1：沒問任何問題就直接動手，靠自己猜的假設寫，結果跟題意不符。

## 解題思路
- 5：自己想出最佳或接近最佳的解法，並說得出為什麼比暴力解好；不需要提示，或只需要一個小提示。
- 3：想得出可行的解法，但要一兩個提示才走到比較好的解法，或沒有比較其他做法。
- 1：卡住或方向錯誤，需要很多提示，最後還是沒有可行的解法。

## 程式實作
- 5：程式正確、結構清楚、命名好懂，善用語言特性和標準函式庫，幾乎沒有 bug。
- 3：主要邏輯正確，但有一兩個 bug 或邊界錯誤，被提醒後改得過來；可讀性普通。
- 1：程式寫不完或無法運作，或跟自己講的解法對不上。

## 溝通表達
- 5：先講思路再動手，邊寫邊講，主動說明取捨，追問也回答得清楚。
- 3：大致有說明，但常常安靜寫很久，或說明零散，要面試官追問才講清楚。
- 1：幾乎不講思路，或講的和寫的對不上。

## 測試與除錯
- 5：主動拿範例逐行走過程式，自己想到並檢查邊界情況（空輸入、重複值、極端值），自己找到並修好 bug。
- 3：被要求才測試，只走過基本範例；部分 bug 要面試官用特定輸入點出來。
- 1：沒有測試，或找不出明顯的 bug。

## 複雜度分析
- 5：時間和空間複雜度都正確，包含遞迴堆疊和輔助資料結構，也說得出瓶頸在哪裡、怎麼改善。
- 3：大致正確，但漏了空間複雜度或某些細節，或需要提示。
- 1：分析錯誤或說不出來。
